Script information

This page documents the scientific-agreement unit tests that guard every species distribution model (SDM) algorithm on the EcoCommons platform. Each test runs a real EcoCommons projection and compares it against an independent reference implementation — the algorithm’s own R package, Valavi et al. (2021)’s published benchmark on the NCEAS nsw14 data, the reference implementations in Hijmans & Elith’s Species distribution modeling with R (the dismo vignette), or our verbatim reproduction of Guisan, Thuiller & Zimmermann’s Habitat Suitability and Distribution Models (2017) on the Vulpes vulpes data (for SRE, FDA, ANN and GBM).

Every SDM agreement test in the EcoCommons R package (tests/testthat/test-sdm_projection_agreement.R) runs a real EcoCommons projection and compares it to a reference benchmark — the algorithm’s own R package, Valavi et al. (2021)’s published benchmark on the NCEAS nsw14 data, or our HSDM (Guisan et al. 2017) Vulpes vulpes reproduction.

Rows 12–16 are the geographic (spatial-only) models — they predict from the geographic location of occurrences, not from environmental predictors — so their reference is the algorithm’s own dismo function as taught in Hijmans & Elith’s Species distribution modeling with R (Chapter 13).

Calibration alignment — every EcoCommons↔︎reference gap turned out to be weighting or rescaling, never the underlying learner:

  • RF, GLM — rescale_all_models = false: RF Pearson 0.89 → 0.99, GLM 0.96 → 0.98.
  • MARS — biomod2 fits earth(glm=binomial, weights=prevalence); the benchmark uses the same background down-weighting: 0.72 → 1.00. (Earlier thought to be an unfixable wrapper difference — it was just the missing weights.)
  • GAM — biomod2 GAM_mgcv applies prevalence=0.5 as presence up-weighting (presence weight = bgNum/prNum, background = 1). For a GAM under UBRE the absolute weight scale drives smoothing-parameter selection, so Valavi’s background down-weighting (same ratio, ~60× smaller total) selects different smoothness: 0.87 → 1.00 once the benchmark matches biomod2’s presence up-weighting (both engines are mgcv).
  • BRT — Valavi down-weights the background; EcoCommons production uses unit weights (down-weighting is proposed, not applied). The nsw14 BRT test mocks the internal weighting to down-weight — matching Valavi’s config (Pearson 1.000) — while the Anguilla BRT test keeps exercising the real unit-weight path (0.985).

Two references, both checked

Like the nsw14 suite, these tests have two distinct reference points:

1. Literature anchor — the textbook’s own reported numbers. Chapter 13 prints a ModelEvaluation (AUC, point-biserial cor) for each model on the Bradypus variegatus data. We reproduce those exactly, to seven decimals. Two things are required to hit them: (a) RNGkind(sample.kind = "Rounding") — the book predates R 3.6.0’s change to the sample() algorithm; and (b) replaying the book’s exact random-number stream (including two incidental rnorm(50) calls in its evaluate() demo) so the train/background splits match.

Reproducibility & benchmark provenance

The single most important thing to understand about these nsw14 benchmarks is what they are a reference to — because it determines when they must be regenerated and what “still matching Valavi” actually means.

Two different reference points

There are two distinct notions of “matching a reference”, and they behave very differently:

Independent reimplementation (what the .tif benchmarks are) Published paper numbers (Valavi’s Models_prediction/*.csv)
Produced by generate_nsw14_valavi_benchmarks.R — Valavi’s exact configs re-run through the algorithm’s own R package (gam, randomForest, earth, dismo::maxent, dismo::gbm.step) Valavi et al. (2021), fixed external artifact
What the test checks Implementation fidelity — does EcoCommons wire up the algorithm the same way an independent implementation does? Literature agreement — do we reproduce the actual published predictions?
Metric used here Pearson on absolute suitability (the agreement tables above) Pearson/Spearman at the 702 evaluation sites (the “reproduce Valavi’s published predictions” table above)
Sensitive to package version? Cancels out — see below Yes — this is the real anchor to the paper

The .tif benchmarks are not frozen EcoCommons snapshots (they come from different engines) and not Valavi’s literal published rasters either. They are a faithful re-run of Valavi’s recipe. So “matching the paper” via these benchmarks means “matching a faithful reproduction of Valavi’s config”, not bit-matching the 2021 output.

What changes the final benchmark

The absolute suitability values written into each benchmark .tif depend on the software environment they were generated in — not just the algorithm and config. In order of impact:

  1. Package version drift. Tree-ensemble learners are the main offender: gbm (BRT) absolute predicted probabilities shift across gbm versions / platforms. randomForest, earth, gam, maxent.jar are far more stable. This is the reproducibility issue that forced the BRT benchmark to be regenerated inside the CI container rather than frozen from a dev machine (newer gbm on macOS drifts on Pearson in CI).
  2. The R version and compiler toolchain (numerical libraries, BLAS).
  3. Config / weighting changes — e.g. background down-weighting, normalisation, hyper-parameters. BRT down-weighting is now applied through the supported site_weight_scheme = "downweight" option in the nsw14_brt spec (no longer a test-only mock), so EcoCommons matches Valavi’s config directly.
  4. The training-point construction — dedup one-per-cell, complete-cases filtering — which is deliberately matched to EcoCommons’ filter.raster.

Because of (1)–(2), benchmarks must be regenerated in the pinned CI container (ec-rpkg-ci-test-env), never on a local dev machine. Locally, R is not renv-activated, so a laptop pulls whatever package versions it happens to have — reintroducing exactly the drift the CI-native benchmark exists to avoid.

Why regenerating in the same environment is safe

When a benchmark is regenerated in a bumped environment, both the benchmark and EcoCommons run through the same new engine (for BRT, the same new gbm). Their absolute values shift together, so their Pearson agreement is preserved. That is precisely why regenerating-in-CI works: it cancels version drift on both sides.

The blind spot: because the two sides move together, a genuine engine change could move both the benchmark and EcoCommons away from Valavi’s 2021 numbers while they still agree with each other. The guard against silently re-baselining away from the paper is twofold:

  • Rank-drift check (in the generator). write_bench() reports the Spearman correlation between each newly generated prediction and the currently committed .tif, and warns if it drops below 0.98. Benign scale drift (a new gbm) leaves rank order intact (Spearman ≈ 1); a low Spearman means the science moved, not just the scale — investigate before committing.
  • Literature anchor. The “reproduce Valavi’s published predictions” table (702-site Pearson/Spearman vs the original CSVs) is the check that actually ties us to the paper, and it is version-robust because it is rank-friendly.

Rule of thumb: benchmark-generation environment == test-execution environment == the pinned container image. Whenever that pin moves (a package patch or a base-image rebuild), regenerate the affected .tif benchmarks in the new environment and commit them alongside the version bump — after confirming the rank-drift guard stays green.

Cross–R-version reproducibility: the four “not-yet-tested” biomod2 learners (SRE · FDA · ANN · GBM)

The algorithm-coverage table above lists SRE, FDA, ANN and GBM as not yet guarded by a scientific-agreement test. As a first step toward covering them — and as a controlled study of what actually breaks reproducibility — we reproduced all four exactly as taught in Guisan, Thuiller & Zimmermann’s Habitat Suitability and Distribution Models (2017; the public hsdm companion code), then re-ran each one under the book’s original 2017 software and under a current stack, and diffed the predictions cell-by-cell.

Why does ANN diverge — didn’t we hold the configuration fixed? We did: identical data, hyper-parameters and seed produced bit-identical initial weights in both versions. A 2×2 experiment crossing the R build with the nnet version isolates the cause:

Comparison Only thing that differs Pearson r
same R 3.4.1; nnet 7.3-12 → 7.3-20 package source 1.000000 (bit-identical)
same nnet 7.3-20; R 3.4.1 → 4.6.1 (both Linux / gcc) R build 0.940
same nnet 7.3-20 / R 4.x; Linux·gcc → macOS·clang·arm64 compiler + CPU 0.951

The nnet package version is not the cause (bit-identical). The divergence comes from the compiled floating-point environment — R build, C compiler, CPU architecture (FMA), and the system libm (exp/log inside the logistic output units) each perturb the arithmetic at the ~10⁻¹⁵ level. Because nnet minimises a non-convex loss by BFGS and never reaches a unique optimum, those perturbations compound into different local minima (final loss 565 vs 572 from the identical start). The magnitude of the disagreement follows the Bernoulli variance p(1−p) — the derivative of the logistic output — peaking at suitability ≈ 0.5 and vanishing at the saturated extremes, which is exactly the “leaf” shape.

ANN cross-version scatter (the “leaf”) and mean disagreement by suitability band; disagreement is ~13× larger near p = 0.5 than at 0/1, tracking p(1−p).

This is the same reproducibility story the benchmark-provenance section tells, pushed to its logical end. There, tree-ensembles (gbm) drift across versions while randomForest / earth / maxent.jar stay stable; here, an unaveraged neural network is the least reproducible learner of the four, and the two mitigations are precisely the ones already in use on the platform:

  1. Pin the environment. A fixed container makes the result bit-identical — confirmed by the old biomod2 3.3-7 sre() matching the modern bm_SRE on 8,542 / 8,542 cells, and by re-running the same nnet source in the same image (r = 1.000000).
  2. Ensemble. Averaging 15 ANN fits recovers r = 0.997 without pinning anything — which is why GBM, an ensemble by construction, barely drifts.

SRE and FDA need neither: a single deterministic quantity has one answer in any environment. The full reproduction (verbatim code, performance, prediction/response-curve figures) and the Docker harness live in the hsdm companion repository.

Methods — metrics for reproduction performance

Every agreement test runs a real EcoCommons projection and compares it, cell by cell over the prediction grid, against an independent benchmark (for the HSDM suite, our verbatim reproduction of the book). We score the two rasters with two complementary correlation metrics, and read the shape of their scatter to diagnose how they (dis)agree.

Two metrics

  • Pearson correlation — agreement on the absolute predicted values. It reaches 1.0 only if the two surfaces are related by a straight line, so it penalises any difference in scale or probability calibration. This is the strict headline metric, used where both engines are on the same 0–1 scale (as on the balanced HSDM Vulpes data).
  • Spearman rank correlation — agreement on the ordering of cells. It reaches 1.0 whenever the two surfaces rank every cell the same way, regardless of the value scale; it is invariant to any monotonic transform (rescaling, a different sigmoid/posterior calibration, etc.).

Why both. For an SDM the ecologically meaningful quantity is usually the ranking of suitability — which places are more suitable, where a threshold falls — not the absolute probability scale. So a high Spearman with a lower Pearson means “same science, different scale”: a benign recalibration, not a scientific disagreement. We report Pearson where the scales match and lean on Spearman when a monotonic scale difference would otherwise understate an exact match.

Reading the agreement scatter

Plotting benchmark (x) against EcoCommons (y) makes the kind of agreement visible:

Scatter shape Meaning Example
Straight line on the 1:1 diagonal exact agreement (Pearson ≈ Spearman ≈ 1) SRE
Clean S-curve, no scatter deterministic monotonic rescaling — identical ranking (Spearman = 1), slightly different value scale; benign FDA (r_s = 1.000, r = 0.999)
Lens / “almond” cloud stochastic disagreement — genuine run-to-run noise, widest in the uncertain mid-range (~0.5) and pinched where predictions saturate (0/1), tracking p(1 − p) GBM (thin), ANN (fat)

The S-curve and the almond are two faces of the same sigmoid output transform: the S is its noiseless skeleton (a pure rescaling), the almond is that skeleton smeared by stochastic noise. A fat almond means large noise (a single ANN’s random weight initialisation → different local minima); GBM’s per-tree bagging almond is by contrast negligible — averaged over 10,000 trees, almost nothing survives — so once its config is matched GBM’s scatter is essentially a straight line.

Deterministic vs stochastic learners

This taxonomy sets the achievable ceiling:

  • Deterministic — SRE (quantile envelope) and FDA (MARS) compute a single fixed answer, so any correct implementation reproduces them to Pearson/Spearman ≈ 1 (FDA’s tiny S is a rank-preserving wrapper hairline, not a disagreement).
  • Stochastic — GBM (bagging) and ANN (random weight init) carry irreducible noise, but they land in very different places. GBM reproduces to ~0.999 with a single fit once its config is matched: its per-tree bagging noise is already averaged away by the 10,000-tree ensemble, so almost nothing survives. (Its earlier 0.955 was a config mismatch — the benchmark used the book’s GBM settings while EcoCommons fell back to biomod2’s defaults — not bagging noise; pinning the config fixes it.) A single ANN fit is the opposite: it does no internal averaging, so it lands in a different local minimum every time and reproduces only to ~0.81 — which is why we test ANN as a 50× ensemble (→ 0.996). The general rule: averaging turns a non-reproducible stochastic learner into a reproducible one — GBM does it internally (10k trees), we do it explicitly for ANN (50 nets).

Per-algorithm pass thresholds reflect this: 0.99 for SRE, FDA and GBM, and 0.95 for the ANN ensemble.

EcoCommons agreement on the HSDM data (SRE · FDA · ANN · GBM)

The cross-version work above validates the reference implementation. The final step closes the loop: does EcoCommons itself reproduce that reference? We converted the book’s Vulpes vulpes data into EcoCommons input fixtures (4,203 presences / 4,339 absences on the 1.5° global grid, with bio3/bio7/bio11/bio12), ran EcoCommons’ own SRE / FDA / ANN / GBM, and scored each projection against our verbatim reproduction of Guisan, Thuiller & Zimmermann (2017) — i.e. the benchmark is the projection we made, not a frozen EcoCommons snapshot. These are now testthat agreement tests in the EcoCommons R package (test-sdm_projection_agreement.R, hsdm_* specs).

Algorithm Engine Nature Pearson Spearman Result
SRE biomod2 (envelope) deterministic 1.000 1.000 ✅ exact
FDA mda (MARS) deterministic 0.999 1.000 ✅ exact
GBM gbm stochastic (bagging) 0.999 0.999 ✅ exact
ANN nnet stochastic — 50× ensemble † 0.996 0.993 ✅ reproduced
† ANN is changed from the book — and why

The book fits a single ANN. But a single neural network is not a reproducible object: its non-convex training lands in an arbitrary local minimum set by the random starting weights, and across seeds the model quality swings wildly (AUC 0.73–0.97 on this data). Two independent implementations therefore never match — the book’s ANN and EcoCommons’ ANN agree only at Pearson ≈ 0.81, and neither is even reproducible run-to-run.

So for ANN we deliberately change the configuration to an ensemble: fit 50 networks, each on a different random 80/20 split, and average them (EcoCommons’ native nb_run_eval = 50). Averaging converges to the stable expected prediction — a well-defined, reproducible target. The payoff: EcoCommons’ 50-net ensemble reproduces our 50-net ensemble at Pearson 0.996, and the EcoCommons ensemble is itself reproducible run-to-run at 0.999 (a single fit was neither). This is a strictly better model than the book’s single fit, and it moves ANN from “the fragile outlier” into the reproducible column. You cannot reproduce one coin flip; you can reproduce the average of 50.

Each row is one algorithm: our HSDM reproduction (left) vs the EcoCommons projection (middle), over the global Vulpes vulpes range, and the site-level agreement (right) — our value at each cell (x) against EcoCommons’ (y), with the 1:1 line and Pearson r. All four scatters collapse onto the 1:1 line and the map columns are visually indistinguishable. On the balanced Vulpes presence/absence with the book’s verbatim configuration both engines sit on the same 0–1 scale, so Pearson (not just rank) is high. ANN is the 50× ensemble (changed from the book — see the note above): a single ANN fit would open into a noisy cloud (Pearson ≈ 0.81, an arbitrary local minimum), but averaging 50 fits converges to a stable, reproducible surface that EcoCommons reproduces to Pearson 0.996.
